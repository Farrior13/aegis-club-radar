2. The Privacy Boundary: What the Public Chain Sees vs. What Stays Cryptographically Hidden

Pedersen Commitments C = v·H + r·G · Halo2-KZG-BN254 · Bulletproofs++ · SP1 Groth16
PUBLIC ON-CHAIN FOOTPRINT What Any Outside Observer Can Read
Visible on BTC + EVM
1. Pedersen Value Commitment C = v·H + r·G (64-byte secp256k1 point) Every note publishes its compressed/uncompressed coordinates (Cx, Cy). Homomorphic addition (ΣC_in = ΣC_out + fee·H) lets verifiers check zero inflation without learning v.
2. Note Leaf Hash & Merkle Tree Position On Ethereum ConfidentialPool, each note appends leaf = keccak256(assetId ‖ Cx ‖ Cy ‖ owner) to the depth-32 Merkle tree (currently 5,853 leaves on ETH, 185,038 on Base TacitEvmPool).
3. Nullifiers (nf) When Notes Are Spent Spending a note reveals a deterministic 32-byte nullifier to prevent double-spends. The nullifier cannot be linked back to which historical leaf index was spent.
4. Public Boundary Crossings (Wrap / Unwrap / Deposit / Withdraw) Entering or exiting the shielded pool from an EVM 0x address (or XNS name label@namespace) reveals the caller's 0x address, the canonical ERC-20/ETH amount crossing the boundary, block timestamp, and gas/relayer fee.
5. Bitcoin Taproot Witness Envelope Header & Opcode On Bitcoin L1, spending the staging Taproot output reveals the script-path witness (OP_FALSE OP_IF "TACIT" <ver> <opcode>), the opcode (T_CETCH, T_CXFER_BPP, T_POOL_BRIDGE_BURN, T_SWAP), and the outer carrier UTXO satoshis (546-sat dust).
CRYPTOGRAPHICALLY SHIELDED What Never Touches the Public Ledger
Information-Theoretically / ZK Hidden
1. Note Amounts (u64 value v) & Blinding Factor (256-bit scalar r) Because C = v·H + r·G is perfectly hiding for random r, even an unbounded adversary cannot extract v from C. Range validity (v ∈ [0, 2^64)) is proven in zero knowledge via Bulletproofs++ (Bitcoin) or SP1/Groth16 (EVM).
2. Sender-to-Recipient Graph & Input-to-Output Linkage Inside settle() on Ethereum or TacitEvmPool.transact(), the ZK proof attests that the spent nullifiers derive from valid Merkle leaves in currentRoot() without revealing which leaves were consumed.
3. Stealth Recipient Identity (tacit1… Address) A tacit1 identifier encodes (spend_pubkey, view_pubkey). Senders perform ECDH with a fresh ephemeral key R = k·G so every note on-chain has a unique one-time owner hash. Searching a tacit1 string on-chain yields zero hits by design.
4. Shielded Balance of Escrow-Wrapped Assets (ETH, USDC, USDT, wstETH) As documented in VERIFY-LIVE.md, the pool's public ERC-20/ETH balances are visible, but the breakdown of who owns those notes inside the tree is completely private.
5. XNS Identity Privacy Nuance (0x6e797ba2d3103aF167918e71a7E01DE40D45f74b) XNS permanently binds label@namespace → 0xAddress. Using a pseudonymous XNS handle (1x45@xns) shared verbally prevents clipboard/chat correlation, whereas a real-name XNS handle (john@xns) permanently de-anonymizes public boundary wraps!
